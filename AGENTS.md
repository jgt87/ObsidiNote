# AGENTS.md — ObsidiNote

Agent notes for this repo. Only what can't be read from the code: commands, misleading places,
and anything that had to be corrected twice; settled decisions live in `DECISIONS.md` and are
cited here by id. Keep it under 200 lines; move long
procedures into a skill and area-only rules into `.claude/rules/<area>.md`.

## What this is
ObsidiNote is a personal wiki that links itself, in the spirit of Markdown note apps. The user adds anything
(text, links, files, mail excerpts) in a local web app. M365 Copilot (driven in Edge over the
DevTools protocol) classifies each item and proposes links to related pages and topics.
ObsidiNote writes the result as pages into its own OneNote notebook through the desktop OneNote
COM API, keeps its own index, and shows everything as a relevance graph. It runs on Windows
PowerShell 5.1 with no install rights. The research and
design are in `FEASIBILITY.md`, and the go/no-go probes are in `probes/`.

## Architecture
Built (interface step 1):
- `obsidinote.ps1`: entry point; start sequence, then `Start-UiServer` and the window; waits on the server's runspace, `finally` stops the server and disconnects the Copilot bridge (kept connected while it runs).
- `lib/Server.psm1`: HttpListener on 127.0.0.1/localhost:<uiPort>, request loop in its own STA runspace (OneNote COM). State crossing into the runspace is a synchronized hashtable of plain values (`New-ServerState`), never scriptblocks (session-state affinity). Checks in order: loopback client, exact Host, exact Origin when sent, POST only on `/api/`, `X-ObsidiNote: 1` on every `/api/` call. Static files only from the allow-list built from `ui\` at start (known web types, no dot-folders). API: `GET /api/status`, `GET /api/notebooks` (open notebooks: id, name, vault, active, location; vaults first), `GET /api/notebook[?id=]` (one notebook's sections and recent pages; the active vault without id; 400 for a non-id, 404 for an id that is not an open notebook), `POST /api/active-vault {id}` (opens that vault with its lease and keeps its record as `"vaultId"` + `"notebook"` in `config\obsidinote.local.json`, the only file the server changes; refuses non-vaults with 409), `POST /api/intent`, plus the step 2-5 routes below. All notebook reads go through `Read-NotebookData` (list/view) on `Get-VaultList`/`Get-NotebookList`. Tests feed it `New-ServerState -FakeHierarchyXml` (tests/fixtures/hierarchy.xml, invented, with state pages; read only) or, in process, `-TestAdapter` (FakeOneNote) and `-TestCopilot`. Page CSP: `default-src 'self'`, no inline script or style.
- `lib/Intent.psm1`: the Add-vs-Ask rules (FEASIBILITY.md), pure; the one implementation (the UI asks the server, it does not copy the rules). Scored since 2026-11-18 (`Get-IntentSignals`; a lead of `$Margin` 2 decides, else unclear and the box offers both, `model/intentWording.ts` `choices`); `POST /api/intent` passes the vault's link rules so a company link with words reads as Add. Every example in `tests/fixtures/intent-samples.json` must hold (`tests/Intent.Tests.ps1`); a reported wrong call becomes an example there first.
- `lib/NotebookView.psm1` (thin, step 1; replaced by the full detection): open notebooks (GetHierarchy hsSections) with a step-1 vault check (a `00 Index` section directly in the notebook, not the name), the active vault (the one on the `"notebook"` record, else the first), one notebook's sections/groups with page counts and the 10 latest pages (GetHierarchy on that notebook, hsPages, + GetHyperlinkToObject), recycle bin left out, only `onenote:` links passed on. An id is only read when it is an open notebook's id. `Find-VaultInHierarchy` is the start's finder (record only when there is one, so a start never switches vault by itself). Never starts OneNote (no COM call when it is not running: COM activation would start it). No OneNote write method anywhere in the interface modules (NoContentOnDisk test).
- `lib/AppWindow.psm1`: with Copilot, `Target.createTarget {newWindow: true}` on ObsidiNote's Edge (an open interface tab is activated instead); with `-NoCopilot`, Edge with the profile and `--app=<url>` (plus the debug port, so a later Copilot start can reuse that Edge), else the default browser.
- `ui-src/`: React + Vite + TS; `src/api.ts` (fetch + types; normalises PS 5.1 one-item/empty arrays; `SubmitResult` = Add | Ask union by `intent`), `src/model/*` pure wording/keys/format/attention/notebooks/handoff (vitest), `src/components/*` with one CSS file each, tokens from `../src/styles/tokens.css`. `src/graph` (knowledge graph, `fetchGraph`), `src/add` (Add result, Undo/Update/Decide), `src/ask` (progress, answer) are the step 3-5 views; `components/HomeView` + `hooks/useHomeFlow` wire the box to them (Save answer = Ask's page spec as Add text, `model/handoff.ts`). Browser storage only in `src/model/preferences.ts`, two keys (`VAULT_KEY`: the active vault's switcher id; `THEME_KEY`: system|light|dark, applied in `main.tsx` before the first render because the CSP allows no inline head script; both validated on read); the NoContentOnDisk test fails on storage anywhere else. Classification: active vault id and theme = user preferences (localStorage + the `"vaultId"`/`"notebook"` record); shown notebook, mode, text, Ask sources/archived, results = session state in memory. Favicons are emitted from `assets/` by a Vite plugin; the rail icon is `assets/icon.svg` inlined.

## Invariants (do not relax)
- Write only inside ObsidiNote's own notebook; other notes, mail and files are copied in, never edited. The user's data is read-only.
- On a page, rewrite only the outlines tagged `<one:Meta name="obsn.role">`; never touch other content (P1, 2026-11-12).
- Copilot is a stateless reasoning step: every id it returns is checked against the index before anything is written.
- **Request reference** (D-105): every Add prompt (classify/link and link summary) carries `ref` (`New-RequestRef`, 'r' + 8 base36, no content) and asks Copilot to repeat it; the link summary also repeats the link as `source`. A live answer with another `ref` is refused; an answer read from the chat later (`Receive-AddAnswer`) is used ONLY when its `ref` is the Intake item's (`obsn.requestRef`) and, for a link, `source` normalizes to the item's link, then checked like a live answer through the same pipeline (`Invoke-AddRequest -Resume`). Never take the last reply on the page without the ref.
- **Add never stops a slow answer**: `Get-AddCopilot` sends with `$script:AddWait` (2 min, D-106: only how long the window stays busy) and `-LeaveRunning` (stall or deadline = Result `Pending` with `ChatUrl`, no Stop; the Intake item becomes `waiting` with `obsn.requestRef/requestKind/waitingSince/chatUrl`, nothing else is written) and `-BusyWaitSec` (Copilot still answering: wait, then `Busy`, never type over it). Other callers keep the default (Stop, then NoAnswer/throw). A link Update that gets `Pending` makes an Intake item "Update: ..." (`requestKind` linkUpdate, or linkSeen for a re-pasted link) that waits the same way; `Receive-AddAnswer` finishes it through `Update-LinkSummary -Resume` (ref and `source` checked) and files the item with the page id.
- **OneNote is the only store** (D-107). Content, the index, the Intake and state live in the ObsidiNote notebook; the app only references it. Never write content to disk: no index or cache files, no temp files with page text, logs hold ids/counts/timings only. Local files hold no content: `config\obsidinote.local.json` (settings), and the updater's backups of the app's own files and `update.log` in `%LOCALAPPDATA%\ObsidiNote`. Single writer = a lease Meta tag on the `ObsidiNote` page, not a lock file (FEASIBILITY.md, storage principle). The one exception (D-108): **Export as Markdown**, a download the person asks for, built in memory (`New-ZipBytes` on a MemoryStream) and sent to the browser; no temp file, no copy kept, the log gets counts only (`MarkdownExport.psm1` is in the NoContentOnDisk store list).
- **Notebook structure is fixed** (D-109; FEASIBILITY.md, Notebook structure): sections `00 Index`, `01 Intake` (was `01 Inbox` until 2026-11-13; `Install-ObsnStructure` renames a vault's own root-level `01 Inbox` once via the guarded `RenameSection`, never when `01 Intake` exists; code names like `CreateInboxItem` keep "Inbox"), then one bucket per page type (`Notes`, `Internal links`, `Web links`, `Sources`, `People`, `Projects`, `Meetings`, `Decisions`, `Journal`/<year>, `Files`, `Archive`). A page's section = its `type` from a fixed list (the validator rejects others); topics live only in the index, never as sections. Max 500 pages per section (rollover `<Bucket> 2`); subpages only for parts of one thing; sections and pages the user made are listed, never edited.
- **Archive and delete** (D-110; FEASIBILITY.md, Archive and delete): archive is the default and reversible (move to `Archive / <bucket>`, keep id/links, Restore). Archive AND delete always ask for confirmation first (one page, selection, topic, Tidy up, typed command; no "don't ask again"). Delete covers only ObsidiNote's own pages and goes only through OneNote's Deleted Pages (60 days); it removes index entries and edges and turns links to the page into "(deleted: title)". Never a permanent delete, never automatic (Tidy up only suggests). "archive …"/"delete …" typed in the box opens the same confirmation, never Add/Ask.
- **Links** (D-111; FEASIBILITY.md, Links): a pasted URL becomes one summary page. Internal (Microsoft 365, `internalHosts`, a company SaaS tenant, the company's name in another domain's subdomain; names from the vault's own SharePoint/OneDrive host, never stored) vs Web (public job boards and hosting, the company's own public domain, the rest) by fixed host rules, no model (`Get-LinkBucket`, D-112). The interface opens a link page's own address first and OneNote second (`url` in Ask sources and graph pages, http(s) only). Copilot reads the source (Work IQ for internal, web grounding for external); store a summary + key facts + link, never the full text; one page per normalized URL (update, never duplicate); the Links index page groups by site/team and domain. **Update** (per link, per site/domain, stale > 90 days) re-reads the source, shows old vs new, keeps the last 3 summaries collapsed on the page, re-runs linking (new links added, outdated ones shown for review, never removed silently), and never touches the page's "Your notes" outline; a hand-edited summary outline is replaced only after asking.
- **Everything is listed in the central index** (D-113): every page id appears in its topic hubs or Unfiled, in By type and in A-Z; on every start and after every write the app compares the hierarchy with the index and adds any missing page to Unfiled. Not listed: `00 Index` and the `01 Intake` requests (`Test-RequestSection` in lib/Index.psm1; listing them showed every Add twice on the map, 2026-11-13). Covered by tests/Index.Tests.ps1.
- The central index is the way into the data: retrieval walks topic paths (root topics, then branch, then pages, then text), and every page has a topic path. The Index section pages are generated by the harness, never edited by hand, and are a mirror of the content pages' own `obsn.*` Meta: when they disagree the page wins, and a rebuild scan regenerates them.
- The Copilot bridge (`lib/CopilotBridge.psm1`, `lib/Cdp.psm1`) writes no files: no reply frames, prompts, reply text, screenshots or lock files; its log holds ids, counts, timings and states only (no prompt or reply text, page titles, banners, file names or URLs with query strings). Enforced by `tests/NoContentOnDisk.Tests.ps1`; do not widen its allow-list, fix the code. When porting a fix from the earlier bridge, drop its debug dumps.
- Never rely on Copilot's own search over OneNote, or on OneNote `FindPages`, for retrieval; use the ObsidiNote index.
- **Write guard**: every OneNote write goes through the guarded adapter (`$Adapter.` / `$Ctx.Adapter.`), whose root is the active vault; no module but `lib/OneNote.psm1` makes a COM object that writes (`lib/NotebookView.psm1`/`OneNoteHost.psm1` only read). Store writes also need a valid writer lease (`AssertWritable`). Enforced by `tests/NoContentOnDisk.Tests.ps1` and `tests/VaultStore.Tests.ps1`.
- **Lease take-over** (D-033): the lease value carries `m` (`Get-MachineMark`, 12 hex of a hash of the computer name, never the name). A lease that is not expired is taken over only when its `m` is this computer's AND the start has just established that no other ObsidiNote runs here (`-NoOtherHere`, start only; never renewal or vault switch). Another mark or no mark: wait for expiry.
- **Tags are set by hand only** (D-034): Add, link Update and Copilot never read or write `obsn.tags`; one normal form (`ConvertTo-TagList` in `lib/PageMeta.psm1`, pinned by `tests/fixtures/tags.json` for server and vitest: change both together); the page's Meta wins over the index record; a page without the Meta has no tags (no upgrade step).
- **Vault invariants**: a vault is found by its state page (`obsn.vaultId`), never by name or by `00 Index` alone; exactly one vault is active, switched only by the person; another vault or a connected notebook is read only, always; making a vault inside a notebook ObsidiNote does not own needs the UI's explicit confirm flag; the "Your notes" outline (`notes`) is written once and `Write-ObsnPage` refuses it on an existing page.

- Keep `docs/STATUS.md` current in the same turn the state changes.

## Releasing
1. Move CHANGELOG `Unreleased` to `## [vX.Y.Z] - YYYY-MM-DD` and write the notes file.
2. Commit and push (clean tree).
3. `tools/build-release.ps1 -Version vX.Y.Z -NotesFile notes.md` bumps `version.txt`, runs the tests, tags, builds `release\ObsidiNote-vX.Y.Z.zip` (one `ObsidiNote\` folder with `version.txt` = the tag and `manifest.json`; no tests/probes/dot-folders), writes SHA256SUMS and publishes both with `gh release create`. `tools/update.ps1` depends on that asset name, the single top folder, `manifest.json` and `SHA256SUMS`: change them together. A release must keep `config\` and `tools\update.ps1`.
