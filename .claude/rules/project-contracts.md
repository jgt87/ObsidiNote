# ObsidiNote: server routes and feature contracts

Moved word for word from AGENTS.md "Architecture" (2026-11-25); AGENTS.md points here. Same upkeep
as there: only what the code cannot show, changed in the same turn as the code.

- Server API added: `GET /api/graph?vault=|notebook=` (active vault without either; connected notebook read only, edges in batches within 15 s, `edgesComplete`), `POST /api/vault/new {name, inNotebook, confirm}` (409 `needsConfirm` without confirm), `POST /api/vault/setup {id, confirm}` (an open, empty notebook set up as a vault in place, `Initialize-EmptyNotebookVault`; 409 `needsConfirm` without confirm, 409 when it holds pages or a vault; the view's `notebook.canSetUp` offers it), `POST /api/submit` (Add or Ask by mode/intent; unclear = Add in auto mode; 503 without Copilot, 409 without a vault), `POST /api/add/undo {undo}`, `POST /api/add/fetch {inboxId}` ("Check for the answer", `Receive-AddAnswer`: an Intake item with status waiting in the active vault, writer lease; 200 with the Add result or still-waiting|mismatch|invalid, 409 not waiting/not the writer), `POST /api/link/update {id, decision, proposed}`, `POST /api/export {scope page|topic|all, vault|notebook, page, topic}` (Markdown download, read only, built in memory by `lib/MarkdownExport.psm1`; the answer is the file itself with Content-Disposition, `Send-Download`). `/api/notebooks` lists vaults (id = notebook id, or the section group id) with `vaultId`, plus `activeVaultId` and `mode`. `POST /api/link/add {from, to[, vault]}` ("Link it", `Add-PageLink` in lib/Ingest.psm1, no Copilot; both ids of the active vault, writer lease; 400/409/404; 200 linked|already-linked; writes the from page's `obsn.links` Meta, the to page's "Linked from" and the index record). `POST /api/page/edit {id, title?, type?, topics?, aliases?, summary?, url?, links?, origin?[, vault]}` (`Edit-Page` in lib/Ingest.psm1, no Copilot; only the sent fields change; a type or address of another section moves the page there (store `MovePage`, result `moved`; refused for an archived page and for a link type, whose section follows its address); writes the title, obsn.* Meta and props outline, never the body or "Your notes"; rewrites "Linked from" of added/removed targets, or of all targets when the title changes; `GET /api/graph` of the active vault carries `types` for the form). `POST /api/copilot/reconnect` (the side bar's refresh button on the Copilot note: one `Connect-Copilot -NoSignInWait -SignInTimeoutSec 15` on the server's only thread, replaces `$State.Copilot`; 200 connected|sign-in|failed, 409 with `-NoCopilot`; `-TestConnect` in tests; `obsidinote.ps1`'s finally also disconnects a replaced bridge). `GET /api/whats-new` (`lib/WhatsNew.psm1`: `{version, updated, notes}` from CHANGELOG.md's section for version.txt, read only; `updated` comes from `obsidinote.ps1` as `New-ServerState -UpdatedTo`; the notice reads only `### Added/Changed/Fixed`).
- Vault settings (D-010, D-011): `lib/VaultSettings.psm1`, one `obsn.settings` Meta (JSON) on the state page: `internalHosts`, `graphView`, `labelsHubsOnly`, `relatedCount` (Add's `RelatedCount`, `Get-AddOptions`), `linkStaleDays` (Ask `Context.StaleDays`), `askIncludeArchived`, `graphShowArchived`, `askMaxPages` (Ask `Context.MaxPages`, 1-50, default 20; branches follow `Get-AskBranchLimit`; step 3 keeps its 75k budget by sharing it, so more pages = less text each; the result's `unused` lists pages read but not cited). `Open-VaultSession` runs `Sync-VaultSettings` (start and vault switch): missing keys added with defaults as the writer, existing and unknown keys never changed, a wrong value kept and the default used in memory; status line `Settings`. Server keeps the values in `$State.VaultSettings` (`Get-ServerLinkRules` reads `internalHosts` there), `GET/POST /api/settings` (writer lease, known keys only). Interface: `model/vaultSettings.ts`, `components/SettingsDialog` (the menu's Settings, Save sends changed keys only), the graph opens with its three defaults and saves Topics/Sources and hubs-only from the map. Export as Markdown is only in the page window and List (D-012). Defaults pinned by `tests/fixtures/vault-settings.json` (server, vitest): change all three together. Local only: `uiPort`, `cdpPort`, `signIn`, `notebook`, `vaultId`, the theme (browser).
- Activity (D-013): `lib/Activity.psm1` (pure) turns the vault's `01 Intake` pages (one GetHierarchy, their obsn.status/filedAs/requestKind) into the home page's "Waiting for Copilot" and History (`src/activity/`); no log or cache. `GET /api/activity`, `POST /api/intake/remove {inboxId}` (only an item that never became a page; writer; to Deleted Pages). Undo from History sends `{id}` only: `Undo-AddRequest` takes the targets from the index record. Edits and "Link it" make no Intake item and are not listed. Recently changed rows carry `pageId` (graph key) and `type` from `lib/NotebookView.psm1` and open the page window through a `FindRequest`.
- Add a file (2026-11-14): `ui-src/src/add/fileText.ts` reads the dropped/picked file's text in the browser in memory (own ZIP reader on `DecompressionStream` for docx/pptx/xlsx, best-effort PDF text, OLE reader for .msg, .eml MIME, text, HTML; 10 MB / 60,000 characters; no third-party code); the text goes through the normal Add with origin `file`. The file never reaches the server or the disk. When the file is in a folder OneDrive syncs (`lib/SyncedFiles.psm1`, `POST /api/file/locate {name,size,modified}`: searches the SyncEngines mount points by name+size+time, reads directory entries only; personal OneDrive's bare UrlNamespace gets the account cid), the Add sends `fileUrl` and becomes that address's link page, summarized from the text (`Options.SourceText` -> `New-LinkSummaryPrompt -SourceText`, Copilot does not open the address).
- Code review fixes (2026-11-15), the contracts they added: `GET /api/activity` carries `vaultId`; `POST /api/add/undo`, `/api/intake/remove` and `/api/add/fetch` take an optional `vault` and answer 409 ("This item belongs to another vault...") when it is not the active vault's id (the window sends it from History, whose rows it empties when the vault changes). Undo also takes the undone page out of the `obsn.links` Meta and index records of the pages that link to it (`Remove-InboundLinks`, result `unlinked`); since the open items below, Undo also rewrites the link in the linking pages' body. Graph pages carry `section` (the page's own section path: `Notes 2`, `Journal/2026`) beside `bucket` (the type bucket); the side bar's section rows search `section:"<path>"` (`ui-src/src/model/sections.ts`), and `tests/fixtures/graph-pages.json` is what the server sends, read by `tests/GraphModel.Tests.ps1` and by vitest: change all three together. One home each: the link rules (`Get-LinkRules` in `lib/NotebookStructure.psm1`, used by the server and the start; another vault's graph uses that vault's own rules, `Get-SourceLinkRules`), the origin check (`Resolve-OriginId`; an Ask ignores origin), the Intake read (`Read-ObsnIntakePages`: that section only, never the vault at page scope). Personal OneDrive hosts (`*.docs.live.net`, `onedrive.live.com`) file as Internal links; the upgrade step `link-bucket` moves old ones. Vault settings that cannot be parsed are left alone (status `unreadable`, defaults in memory, `POST /api/settings` 400). Sources: "Other company sites" has kind `other-internal`.
- Open items (2026-11-15), the contracts they added. Start: after "This computer" comes `Earlier start` (`lib/Startup.psm1` `Invoke-ReplaceRunning`: `POST /api/shutdown` to the running one (200 `{stopping:true}`, the loop ends after the answer, its `finally` gives the lease back), wait up to 10 s, else stop leftover `powershell.exe` whose command line holds this script's full path, never itself or its parents, and not its tree so Edge stays; a line only when something was found), then OneNote and the vault with `-NoOtherHere` from that step. `GET /api/status` `vault` = `{name, vaultId, mode, reason, since, detail}` (`Get-VaultModeInfo`: reason '' | this-pc | other-pc | not-opened, from the lease record the start keeps); `GET /api/graph` `source.readOnlyReason` ('' | lease | not-active | notebook), pages carry `tags`, the model `tags: [{name,count}]`; the interface words them in `model/attention.ts` `vaultNote` and `graph/readOnly.ts`. Tags: `POST /api/pages/tag {ids, add, remove[, vault]}` (`Set-PageTags`, everything checked before anything is written; 200 `{changed, pages:[{id,tags}], warnings}`), `POST /api/tags/rename {from, to[, vault]}` (to '' removes), `POST /api/page/edit` takes `tags`; interface in `ui-src/src/graph/tags.ts`, `TagsRow`, `tagView.ts` (the map's third grouping Topics | Sources | Tags: one area per chosen tag, only tagged pages, a page under its rarest shown tag; session state, the vault's `graphView` setting knows topics and sources only), `components/TagsSettings`. Undo rewrites a link to the undone page in the linking pages' own body outline (`obsn.role` = body only) to "(deleted: title)" (store `RewriteBodyLinks`, result `rewritten`; only pages that link to it in their Meta are checked). `GET /api/settings` carries `message` and `canChange` false when the stored settings are unreadable. A JSON body that must be an object is tested with `Test-JsonObject`. A most linked page is "most linked" in the interface; "hub" means a map area.
- Design round 2 (D-098, D-099, D-100, D-101, D-102, D-103, D-104): `GET /api/page/body?page=<id>[&vault=|&notebook=]` (the page window's text: `{id, markdown, truncated, length}` from `Get-PageBody` in `lib/MarkdownExport.psm1`, the export's converter with `-LinkStyle page` and the summary outline left out, links to pages of the map as `[text](obsn:<id>)`, cut at 20,000 characters at a line break; source through `Get-ExportSource` as `POST /api/export` scope page; read only, in memory, log counts only; pinned by `tests/fixtures/page-body.json`, read by `tests/PageBody.Tests.ps1` and by vitest `graph/bodyText.test.ts`: change them together). Interface: `graph/bodyText.ts` (pure Markdown -> blocks; text nodes only, links only obsn/http(s)/mailto/onenote) + `PageBody.tsx`; `graph/InlineText.tsx` (title and summary changed in place through `POST /api/page/edit`; rules `titleProblem`/`summaryProblem` in `editModel.ts`, shared with the form); the Tags grouping lays the pages of one topic together and names it (`GraphPage.group` set by `tagView.ts`, `placeDots` anchors and `groupLabels` in `layout.ts`, names placed last at the fitted zoom's real size, on no dot; geometry tests in `tagView.test.ts`); the tag picker, `joinLines` and the dashed lines are gone; `FilterButton` carries "Show on the map" (links, mentions, hubs only); `components/ReadOnlyBanner` is the one place that says why (app shell for home/History from `vaultNote`, the graph for its source from `readOnlyWhy`; no side bar note); `--pressed` (neutral) is the fill of every choice that is on, the accent only for the primary action, focus and the focused page (DESIGN.md "One Purple").
- The active vault is kept (D-035): `Get-VaultData` (lib/Server.psm1) is the one place the server learns which vaults are open; it puts the active vault back from `$State.Vault` (`Join-ActiveVault`, lib/VaultSession.psm1, pure) when a detection does not list it while its notebook is still open, so the list, the graph (all three query forms), export, page body, Ask sources, vault switch and set-up keep treating it as the active vault (tests/ActiveVaultKept.Tests.ps1). At start the vault step goes through `Find-StartVault`: when `"vaultId"` and `"notebook"` are on record, that notebook is open, no vault is found in it and it is not the notebook OneNote shows, it selects the notebook in OneNote once (`NavigateTo`, not a write, only at start, only for an open notebook's id), re-reads up to 5 times 2 s apart, and prints one extra `[OK]/[WARN] Vault` line only then. Kit V6 has the read-only "Reads of notebook" lines (per open notebook: selected or not, section counts, Index pages with Meta, state page found), RB-05 step 3a. What OneNote really returns for a non-selected notebook is NOT verified: the fake's two forms (no sections; Index pages without Meta) are guesses until that kit step was run.
- "Check again" (D-036): `POST /api/vault/check-lease` (`Invoke-LeaseCheckRoute`, lib/Server.psm1) runs the same `Update-SessionLease` as the start's minute renewal, under `$State.Lock`, and answers the vault state; it takes only a free or run-out lease. `GET /api/status` `vault` carries `until` (the holder's lease end) and `renewed` (until minus the TTL); the window's `leaseCheckNote` (model/attention.ts) reads a holder renewed within 90 s as still running.
- Archive, restore, delete and stale links (D-038): `POST /api/pages/archive|delete {ids, confirm[, vault]}` (409 `needsConfirm` + `plan {pages:[{id,title,section,to,inbound}], refused}` without `confirm: true`, a boolean; nothing written) and `POST /api/pages/restore {ids[, vault]}` (no confirm: the undo of an archive); `Get-RetirePlan` / `Invoke-PageRetire` in lib/Ingest.psm1. Archive = `MovePage` to `Archive/<bucket>` + `obsn.status` archived + `obsn.archivedFrom`; restore moves back to archivedFrom without its rollover number (else the type's bucket); delete = `Invoke-PageRemoval`, the one removal path, shared with Undo. Only pages of Ingest's index (ObsidiNote's own). A moved page gets a new hierarchy id and link (on a business tenant a new page-id too: kit P1c), so the "Linked from" of its targets is rewritten, and the store's `MovePage` points links to it in the body outline of the pages that link to it at the new link (2026-11-16; every move: Archive, Restore, Edit, upgrade); upgrade step `body-links` repairs links an earlier Archive left dead (`Repair-ObsnBodyLinks`: dead page-id AND text = a linked page's title or alias). Interface: `graph/retireModel.ts` (plan, result, confirm wording), `useRetireFlow.tsx` + `RetireDialog.tsx` (always asks; Delete focuses Cancel; the final Delete is the one solid ink fill), the page window's Archive/Restore/Delete, the List's selection bar. Graph pages carry `summarizedAt` (graph-pages.json); `graph/linkUpdateRun.ts` + `LinkUpdateBar.tsx` run `POST /api/link/update` one page at a time ("Update summaries"), the Filter's `staleBefore` uses the vault's `linkStaleDays`. Not verified on desktop OneNote: probe P1c (an `onenote:` link in another page's text after the target moved to the Archive).
- Journal, duplicates, web links (D-060, D-063, D-062): a text Add typed `log` goes into today's day page "yyyy-MM-dd" (`lib/Journal.psm1`, pure; `Invoke-JournalAdd` / `Undo-JournalEntry` in lib/Ingest.psm1; store `JournalEntry`, optional, not in the contract): one entry = one top-level OE of the body outline (`Add-ObsnBodyEntry` / `Remove-ObsnBodyEntry` in lib/PageMeta.psm1, the outline sent whole by objectID) + one item of `obsn.entries` (split key, same order); the day's topics/links/summary are the union (`Merge-JournalDay`). Undo record and History rows carry `entry` (the request ref); undo of one entry refuses when its line is not where it was written. A day page = type log + date title + entries; older log pages are never merged. Records carry `created` (hierarchy `dateTime`, read at every scan; not in the Index entries) and graph pages `created` + `entries`, pinned by `tests/fixtures/journal-pages.json` (tests/Journal.Tests.ps1 and `ui-src/src/journal/journalModel.test.ts`: change all three together). Interface: `src/journal/` (view in the menu, built from the active vault's graph, no route of its own; without a search it lists day-page entries, older log pages and meeting pages (type meeting, on their created day, no time; D-061); Decisions = decision pages + linked pages; "Find decisions with Copilot" = an Ask hand-off, `decisionsAskText`). Duplicates: `Test-LinkReply`'s refusal gives the result `duplicateOf`; `POST /api/submit` takes `allowDuplicate`; the map's Filter has "Possible duplicates" (`graph/duplicates.ts`). Web links: `POST /api/open {url}` (`Invoke-OpenUrlRoute`, http(s) only via `Test-WebAddress`, `Start-Process`; `State.OpenedUrls` records instead in tests); every web link in the window is `components/WebLink` (a real link; a plain click goes to the server, which falls back to `window.open`). Kit V6 `-WriteTest` "Journal day page" checks the day page on real OneNote.
- A link with words (D-066): `Get-LinkWithNotes` (lib/LinkCapture.psm1, pure: exactly one distinct http(s) address, other words of at most 4000 characters, not a pasted mail) and, in `Invoke-AddRequest`, only for an internal link (store `LinkBucket` = Internal links): the link Add with `Options.LinkNotes` (written into the new page's "Your notes" outline, `New-LinkNotesLines -Text`) and `Options.IntakeText` (the Intake item keeps the whole text, so `Receive-AddAnswer` derives the words again). A link that has a page is updated and the words are not written, with a warning. Tests: `tests/Ingest.Tests.ps1` "A SharePoint link with your own words".
